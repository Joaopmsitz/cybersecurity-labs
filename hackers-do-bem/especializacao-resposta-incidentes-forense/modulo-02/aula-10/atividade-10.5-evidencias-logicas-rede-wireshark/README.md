## 3. Network Forensics Concepts

### Packet Capture Analysis

A packet capture stores network traffic recorded from an interface.

The captured traffic can be examined after acquisition without repeating the original capture.

Wireshark provides protocol dissection and filtering capabilities that help analysts inspect the contents and metadata of captured packets.

### HTTP Traffic

HTTP is an application-layer protocol used to transfer web resources between clients and servers.

Depending on the capture contents, HTTP traffic may contain:

- HTML documents.
- Images.
- Executable files.
- Documents.
- Other files transferred through HTTP.

A packet capture can preserve the data required to reconstruct these objects when the traffic and payload are available.

### Export Objects

Wireshark includes an Export Objects function that can reconstruct selected application-layer objects from captured protocol streams.

For HTTP, the relevant menu is:

```text
File → Export Objects → HTTP
```

The dialog displays objects identified in the capture and provides options to save selected objects or save all available objects.

The list can include fields such as packet number, hostname, content type, size, and filename.

## 4. Procedure

### Step 1 — Open the Network Capture

The PCAP file created during Activity 10.4 was opened in Wireshark.

The capture provides the packet data used in the investigation.

The file can be opened through:

```text
File → Open
```

The PCAP file generated by tcpdump is then selected.

After the capture loads, Wireshark displays the packet list and associated packet details.

### Step 2 — Examine the Captured Traffic

The packet list can be used to inspect the protocols and communications present in the capture.

Wireshark separates packet information into distinct sections:

| Section | Information |
|---|---|
| Packet List | Captured packets and summary fields |
| Packet Details | Decoded protocol layers and fields |
| Packet Bytes | Raw packet data in hexadecimal and ASCII form |

The analyst can inspect HTTP packets and identify communications that contain transferred objects.

### Step 3 — Open the HTTP Export Objects Dialog

The HTTP object extraction function was accessed through the menu:

```text
File → Export Objects → HTTP
```

Wireshark analyzes the selected capture's HTTP streams and lists the objects it can reconstruct.

The dialog can display the following fields:

| Column | Description |
|---|---|
| Packet | Packet number associated with the object |
| Hostname | Hostname of the server that transferred the object |
| Content Type | MIME type associated with the object |
| Size | Object size in bytes |
| Filename | Filename identified for the transferred object |

These fields help correlate an exported object with the network communication from which it was recovered.

### Step 4 — Select and Export the HTTP Object

The HTTP object list was examined to identify the object of interest.

Wireshark provides two relevant options:

| Option | Function |
|---|---|
| Save | Saves the selected object using a chosen destination |
| Save All | Saves all listed objects to a selected directory |

The selected object can be exported to a directory for subsequent examination.

The exact filename, content type, and size depend on the contents of the PCAP file. The activity summary supplied for this documentation does not preserve those literal values.

### Step 5 — Preserve the Exported Object

After export, the recovered object should be preserved for forensic examination.

The exported file can be examined independently of Wireshark.

The relationship between the exported object and the originating network traffic should be retained where possible, including the packet number, hostname, filename, content type, and size shown in the export dialog.

The activity notes available here do not include the exact exported filenames or object sizes, so no specific object is claimed as a result.

## 6. Technical Analysis

### HTTP Object Reconstruction

Wireshark's Export Objects function scans protocol streams in the selected capture and reconstructs objects that can be saved to disk.

For HTTP, this may include documents, images, executables, and other files transferred in the captured sessions.

The exported object is not simply a screenshot or textual representation of a packet. It is a reconstructed file obtained from the application-layer data available in the capture.

### Relationship Between PCAP and Exported Objects

The PCAP file preserves the captured packets.

The exported object is derived from the application data reconstructed from those packets.

The two artifacts serve different purposes:

| Artifact | Forensic Value |
|---|---|
| PCAP file | Preserves packet-level network evidence |
| Exported HTTP object | Provides the reconstructed transferred file |

The PCAP should be preserved alongside the exported object so that the extraction can be reviewed and correlated with its original traffic.

### Limitations of HTTP Export

The Export Objects feature depends on the relevant protocol data being present in the capture.

If the traffic is encrypted with HTTPS, the HTTP payload is not ordinarily available for reconstruction without the necessary decryption material.

Incomplete captures, packet loss, or missing parts of a TCP stream can also affect reconstruction.

Therefore, the absence of an exported object does not necessarily prove that no file was transferred.

### Evidence Correlation

The export dialog provides metadata that can support correlation between the recovered file and its network activity.

Useful information includes:

- Packet number.
- Hostname.
- Content type.
- Object size.
- Filename.

Where available, these details should be recorded with the exported file and the original PCAP.

The activity demonstrates how Wireshark can be used to analyze a packet capture and recover objects transferred over HTTP.

The exported files provide additional artifacts for forensic analysis and can help identify content transferred during the observed network communication.
