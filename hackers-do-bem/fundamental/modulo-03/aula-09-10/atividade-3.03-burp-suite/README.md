# Activity 3.03 — Configuring and Using Burp Suite

> **Program:** Hackers do Bem  
> **Stage:** Fundamental — Module 03  
> **Class:** 09–10  
> **Environment:** Kali Linux  
> **Status:** Completed

## Objective

Configure Burp Suite as a local proxy to intercept and analyze HTTP/HTTPS requests generated by a browser in a controlled laboratory environment.

The activity demonstrates how browser traffic can be routed through a local proxy to inspect requests, headers, and other elements of HTTP communication.

## Environment

- **Operating system:** Kali Linux
- **Tool:** Burp Suite Community Edition
- **Browser:** Mozilla Firefox
- **Proxy:** `127.0.0.1:8080`
- **Environment:** Controlled laboratory

## Procedure

### 1. Launch Burp Suite

The following command was executed in the terminal:

```bash
burpsuite
```

On the Burp Suite welcome screen, the following option was selected:

```text
Temporary Project
```

The following sequence was then selected:

```text
Next → Use Burp defaults → Start Burp
```

Burp Suite started with its default configuration.

### 2. Check the Proxy

After starting the application, the following section was opened:

```text
Proxy → Intercept
```

Initially, interception was disabled:

```text
Intercept is off
```

This setting was maintained during the browser configuration process.

### 3. Verify the Proxy Listener

The following section was opened:

```text
Proxy → Proxy settings
```

The listener configured for Burp Suite was verified.

The listener address was:

```text
127.0.0.1:8080
```

This listener allows local applications, such as Firefox, to forward their HTTP requests to Burp Suite.

### 4. Perform an Initial Browser Test

Firefox was used to access:

```text
http://burp
```

At this point, the browser was not yet configured to use Burp Suite as its proxy, so the page did not load as expected.

This confirmed that the proxy still needed to be configured manually in Firefox.

### 5. Configure the Proxy in Firefox

The following settings were opened in Firefox:

```text
Settings → Network Settings → Settings
```

The following option was selected:

```text
Manual proxy configuration
```

The following values were configured:

```text
HTTP Proxy: 127.0.0.1
Port: 8080
```

The option to use this configuration for HTTPS connections was also enabled.

This configuration allowed browser traffic to be forwarded to Burp Suite's local listener.

### 6. Test Communication with Burp Suite

After configuring the proxy, the following address was accessed again:

```text
http://burp
```

This time, the Burp Suite page was available through the local proxy.

The following page was displayed:

```text
Burp Suite Community Edition
```

This confirmed that Firefox was communicating with Burp Suite through:

```text
127.0.0.1:8080
```

### 7. Download the CA Certificate

To enable the inspection of HTTPS connections, the following address was accessed again:

```text
http://burp
```

The Burp Suite page was used to download the certificate:

```text
cacert.der
```

Burp Suite uses this certificate as a local certificate authority (CA) when inspecting HTTPS traffic in the laboratory environment.

### 8. Import the Certificate into Firefox

The following section was opened in Firefox:

```text
Settings → Privacy & Security → Certificates → View Certificates
```

In the certificate manager, the following option was selected:

```text
Import
```

The downloaded file was selected:

```text
cacert.der
```

During import, the appropriate trust option was enabled so that Firefox could trust the certificate when validating sites during HTTPS inspection.

Trusting Burp Suite's CA allows the browser to accept certificates generated by Burp for intercepted HTTPS connections. This setting should be limited to the authorized testing environment.

### 9. Enable Interception

After configuring the certificate, Burp Suite was reopened:

```text
Proxy → Intercept
```

The option was changed to:

```text
Intercept is on
```

With interception enabled, requests made by Firefox could be paused by Burp Suite before being forwarded to the destination server.

### 10. Access the Test Website

With the proxy configured and interception enabled, the following website was accessed through Firefox:

```text
https://casasbahia.com.br/
```

The request was intercepted by Burp Suite.

At this stage, the browser waited while the request remained available for inspection in the proxy.

This procedure should be performed only against systems and traffic that are within the authorized scope of the laboratory or assessment.

### 11. Analyze the Intercepted Request

The interception screen displayed HTTP request information, including headers such as:

```text
Host:
Cookie:
User-Agent:
```

These fields provide information about different aspects of the communication between the browser and the server.

#### Host

Identifies the hostname to which the request is directed.

#### Cookie

Can contain information stored by the browser and associated with a website's session or functionality. Cookies may contain sensitive session identifiers and should be treated as confidential.

#### User-Agent

Describes characteristics of the client making the request, such as the browser and operating system.

### 12. Review HTTP History

In addition to real-time interception, the following section was opened:

```text
Proxy → HTTP history
```

This area displays the history of requests observed by Burp Suite.

It was possible to review requests made by the browser, including their HTTP methods, URLs, response status codes, and other traffic-related information.

HTTP History is useful for reviewing the communications captured during a test without relying exclusively on the live interception view.

### 13. Capture the Required Evidence

The evidence requested by the laboratory instructions corresponds to **Step 21**, showing the HTTP history in Burp Suite with the captured requests.

The screenshot was taken with the Burp Suite window maximized, following the laboratory instructions.

### 14. Forward Intercepted Requests

After reviewing the requests, the following option was used:

```text
Forward
```

This forwarded the intercepted requests to their destination.

Because some pages generate multiple requests, the **Forward** button had to be used several times to allow the page to continue loading.

Once the required requests had been forwarded, the page continued loading normally.

### 15. Restore Firefox Network Settings

After completing the analysis, the manual proxy configuration was removed from Firefox.

The network configuration was restored to:

```text
No Proxy
```

This step is important because it prevents the browser from continuing to depend on Burp Suite for connections after the laboratory exercise has finished.

## Tools and Configuration Used

The main tool used during the activity was Burp Suite Community Edition.

The following configuration was applied:

| Setting | Value |
|---|---|
| Browser | Mozilla Firefox |
| Proxy address | `127.0.0.1` |
| Proxy port | `8080` |
| Proxy listener | `127.0.0.1:8080` |
| CA certificate | `cacert.der` |
| Interception | Enabled during request analysis |
| Final Firefox proxy setting | `No Proxy` |

## Concepts Practiced

### Proxy

A proxy acts as an intermediary between a client and a server. In this laboratory, Burp Suite was used as a local proxy to inspect traffic generated by the browser.

### Loopback Address

The address:

```text
127.0.0.1
```

refers to the local machine. Burp Suite used this address to expose its local proxy listener.

### Port 8080

The port:

```text
8080
```

was used by the Burp Suite proxy listener.

### Intercept

The **Intercept** feature allows a request to be paused before it is forwarded to its destination, making it possible to inspect the request.

### Forward

The **Forward** action releases an intercepted request so that it can continue to the server.

### HTTP History

HTTP History records the requests observed by Burp Suite, allowing captured traffic to be reviewed and analyzed later.

### HTTPS and CA Certificates

HTTPS uses TLS to protect communication between clients and servers. To inspect HTTPS traffic in this laboratory, Burp Suite's CA certificate was imported and trusted by Firefox.

This configuration allows Burp Suite to generate certificates accepted by the browser for intercepted connections. It should be used only where inspection is authorized.

### HTTP Headers

HTTP headers are part of HTTP requests and responses. They carry information used by the client and server during communication, including the target host, cookies, and client characteristics.

## Results

The activity demonstrated how to configure Burp Suite as a local proxy and observe the flow of browser requests.

During the exercise, it was possible to:

- Launch Burp Suite.
- Verify the local proxy listener.
- Configure Firefox to use `127.0.0.1:8080`.
- Import and trust Burp Suite's CA certificate.
- Intercept an HTTPS request.
- Inspect HTTP headers.
- Review the HTTP History.
- Forward intercepted requests using **Forward**.
- Restore the browser's original proxy configuration.

The laboratory provided practical experience with interception proxies and their use in HTTP/HTTPS traffic analysis within a controlled environment.
