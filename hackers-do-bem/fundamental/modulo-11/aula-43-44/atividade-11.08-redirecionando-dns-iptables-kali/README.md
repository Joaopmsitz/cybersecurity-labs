# Activity 11.08 — Redirecting DNS Requests Using iptables on Kali Linux

## Objective

Use **iptables** on Kali Linux to redirect DNS requests using a **DNAT** rule, observe the effect of the change on name resolution, and verify the configuration of the `nat` table.

---

## Environment

- **Operating system:** Kali GNU/Linux
- **Access:** RDP
- **Tool:** `iptables`
- **Network interface:** `eth0`
- **DNS port used in the lab:** `53/UDP`
- **Configured destination:** `127.0.0.1:53`

---

## 1. Accessing Kali Linux

Kali Linux was started and accessed via RDP.

After opening the Terminal, administrative privileges were obtained using:

```bash
sudo -i
```

---

## 2. Testing DNS Resolution Normally

Mozilla Firefox was opened in a private browsing window using the following keyboard shortcut:

```text
Ctrl + Shift + P
```

Next, the following website was accessed:

```text
https://www.facebook.com/
```

The website loaded normally.

This initial access served as a baseline for verifying the system's behavior before applying the DNS redirection rule.

After the test, the browser was closed.

---

## 3. Creating the DNS Redirection Rule

The following command was executed in the Terminal:

```bash
iptables -t nat -A OUTPUT -p udp --dport 53 -j DNAT --to-destination 127.0.0.1:53
```

The rule was added to the `nat` table, in the `OUTPUT` chain.

### Parameters Used

#### `-t nat`

Selects the **NAT** (*Network Address Translation*) table.

This table is used to perform modifications related to packet addresses and ports.

#### `-A OUTPUT`

Adds the rule to the `OUTPUT` chain.

The `OUTPUT` chain processes packets generated by the local system.

#### `-p udp`

Specifies that the rule applies to the **UDP** protocol.

Traditional DNS queries frequently use UDP.

#### `--dport 53`

Selects traffic destined for port:

```text
53
```

Port 53 is the traditional port used by the DNS service.

#### `-j DNAT`

Specifies the **Destination NAT** action, which is used to change the destination of a packet.

#### `--to-destination 127.0.0.1:53`

Specifies the new destination:

```text
127.0.0.1:53
```

This redirects UDP requests destined for port 53 to the local machine itself, on port 53.

The configured flow can be represented as follows:

```text
Application
   ↓
DNS query over UDP/53
   ↓
iptables / nat table
   ↓
OUTPUT
   ↓
DNAT
   ↓
127.0.0.1:53
```

---

## 4. Testing the Effect of the Redirection

After adding the rule, Mozilla Firefox was opened again in private browsing mode.

The following website was accessed:

```text
https://www.facebook.com/
```

After the redirection was applied, the browser could no longer resolve the address normally.

The following message was displayed:

```text
Hmm. We’re having trouble finding that site.
```

This behavior demonstrates the effect of the change made to the DNS queries used by the browser in the lab environment.

> **Note:** The rule created specifically affects **UDP traffic on port 53**. Therefore, it does not represent a universal block of every modern DNS resolution mechanism, which may use other transport methods, such as DNS over HTTPS (DoH) or DNS over TLS (DoT).

---

## 5. Verifying the NAT Table

To view the existing rules in the `nat` table, the following command was executed:

```bash
iptables -t nat -L
```

The displayed output was:

```text
┌──(root㉿kali)-[~]
└─# iptables -t nat -L
Chain PREROUTING (policy ACCEPT)
target     prot opt source               destination
DOCKER     all  --  anywhere             anywhere             ADDRTYPE match dst-type LOCAL

Chain INPUT (policy ACCEPT)
target     prot opt source               destination

Chain OUTPUT (policy ACCEPT)
target     prot opt source               destination
DOCKER     all  --  anywhere             !loopback/8           ADDRTYPE match dst-type LOCAL
DNAT       udp  --  anywhere             anywhere             udp dpt:domain to:127.0.0.1:53

Chain POSTROUTING (policy ACCEPT)
target     prot opt source               destination
MASQUERADE  all  --  172.17.0.0/16        anywhere

Chain DOCKER (2 references)
target     prot opt source               destination
RETURN     all  --  anywhere             anywhere
```

The added rule can be identified in the `OUTPUT` chain:

```text
DNAT       udp  --  anywhere  anywhere  udp dpt:domain to:127.0.0.1:53
```

This shows that UDP traffic destined for the DNS port (`53`) is being redirected to `127.0.0.1:53`.

## 6. Removing the DNAT Rule

After verifying the redirection behavior, the rule was removed using:

```bash
iptables -t nat -D OUTPUT -p udp --dport 53 -j DNAT --to-destination 127.0.0.1:53
```

The parameter:

```text
-D
```

removes an existing rule.

The remaining parameters correspond to the rule created previously, allowing `iptables` to identify the specific configuration to remove.

---

## 7. Verifying the Rule Removal

After deleting the rule, the following command was executed again:

```bash
iptables -t nat -L
```

The output no longer displayed the previously created `DNAT` rule:

```text
┌──(root㉿kali)-[~]
└─# iptables -t nat -L
Chain PREROUTING (policy ACCEPT)
target     prot opt source               destination
DOCKER     all  --  anywhere             anywhere             ADDRTYPE match dst-type LOCAL

Chain INPUT (policy ACCEPT)
target     prot opt source               destination

Chain OUTPUT (policy ACCEPT)
target     prot opt source               destination
DOCKER     all  --  anywhere             !ip-127-0-0-0.ec2.internal/8  ADDRTYPE match dst-type LOCAL

Chain POSTROUTING (policy ACCEPT)
target     prot opt source               destination
MASQUERADE  all  --  ip-172-17-0-0.ec2.internal/16  anywhere

Chain DOCKER (2 references)
target     prot opt source               destination
RETURN     all  --  anywhere             anywhere
```

The absence of the `DNAT` rule confirms that the redirection created during the lab was removed.

---

## 8. Confirming DNS Resolution Again

After removing the rule, Firefox was refreshed, and the following address was accessed again:

```text
https://www.facebook.com/
```

The website loaded normally again, demonstrating that the rule responsible for redirecting DNS queries had been removed.

After confirming access, the browser was closed.

---

## Key Concepts

- **DNS:** A system responsible for resolving domain names into IP addresses.
- **iptables:** A tool for configuring Netfilter rules on Linux.
- **NAT:** A mechanism used to modify packet addressing information.
- **DNAT:** Changes the destination of a packet.
- **OUTPUT:** A chain responsible for traffic generated by the local system.
- **UDP/53:** A traditional combination used for DNS queries.
- **Loopback:** An interface used to communicate with the local system, represented by `127.0.0.1`.

## Result

A DNAT rule was created in `iptables` to redirect **UDP traffic destined for port 53** to `127.0.0.1:53`. After the rule was applied, access to Facebook failed due to a name resolution error in the lab environment. The rule was subsequently removed, and access returned to normal.
