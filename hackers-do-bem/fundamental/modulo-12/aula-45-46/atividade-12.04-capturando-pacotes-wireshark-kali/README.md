# Activity 12.04 — Capturing Packets with Wireshark on Kali Linux

## Objective

Capture network traffic on **Kali Linux** using **Wireshark**, access an HTTPS website while the capture is running, and analyze the transmitted packets.

At the end of the activity, the **Follow → TCP Stream** feature will be used to view the contents of a TCP stream and observe the effect of TLS encryption on application data.

---

## Environment

- **Operating system:** Kali Linux
- **Tool:** Wireshark
- **Network interface:** `eth0`
- **IP address:** `192.168.98.40`
- **Website accessed:** `https://esr.rnp.br/`
- **Protocol analyzed:** TCP/TLS
- **Port:** `443`

---

Kali Linux was started and accessed via RDP.

After logging in, a terminal was opened and administrative privileges were obtained using:


## 3. Opening Wireshark

The **Wireshark** application was opened from the Kali Linux applications menu.

The initial screen displayed the network interfaces available for packet capture.

---

## 4. Starting the Capture on the `eth0` Interface

In the Wireshark interface list, the following interface was located:

```text
eth0
```

The `eth0` interface was double-clicked to start capturing packets.

From that moment, Wireshark began monitoring the traffic passing through the interface.

---

## 5. Generating HTTPS Traffic

While the capture was running, Firefox was opened.

The following website was accessed in the browser:

```text
https://esr.rnp.br/
```

The page loaded while Wireshark recorded the network packets generated by the communication.

After waiting a few moments to generate sufficient traffic, Firefox was closed.

---

## 6. Stopping the Capture

After returning to Wireshark, the capture was stopped using the stop button, represented by a red square on the toolbar.

The captured packets remained available for analysis in the main Wireshark window.

---

## 7. Understanding Packet Information

In the Wireshark packet list, the following columns used to identify and analyze traffic were observed:

- **Time:** The time when the packet was captured.
- **Source:** The source address of the packet.
- **Destination:** The destination address.
- **Protocol:** The protocol identified in the packet.
- **Length:** The size of the packet.
- **Info:** Additional information about the packet contents or the observed operation.

This information makes it possible to analyze communication between the different hosts involved in the connection.

---

## 8. Filtering HTTPS Traffic

To focus the analysis on TCP traffic associated with the HTTPS port, the following display filter was used:

```text
tcp.port == 443
```

This filter instructs Wireshark to display TCP packets whose source or destination port is `443`, which is commonly used for HTTPS connections.

In the capture, traffic associated with the secure communication established by the browser could be observed.

Depending on the connection and the negotiated version, Wireshark may identify TLS protocols such as **TLS 1.2** or **TLS 1.3**.

---

## 9. Following the TCP Stream

After locating a packet belonging to the HTTPS communication, the packet was right-clicked.

The following option was selected from the context menu:

```text
Follow → TCP Stream
```

Wireshark then opened a window displaying the data associated with the selected TCP stream.

---

## 10. Analyzing the TCP Stream Contents

The content displayed in the **Follow TCP Stream** window did not appear as readable text.

This occurs because communication over HTTPS uses **TLS to protect application-layer data**.

During an HTTPS connection, network information such as addresses, ports, packet sizes, and other metadata can be observed. However, the application content is protected by TLS session encryption.

Therefore, when following the TCP stream without the keys required to decrypt the session, the transmitted application data is not displayed as readable text.

In an unencrypted HTTP communication, application content could appear in a much more easily interpretable form within the TCP stream.

## Key Concepts

- **Wireshark:** A protocol analyzer used to capture and examine network traffic.
- **TCP:** A connection-oriented protocol used to transport data.
- **HTTPS:** HTTP communication protected by TLS.
- **TLS:** A cryptographic protocol used to secure communication.
- **TCP Stream:** A collection of data belonging to a specific TCP flow.
- **Display filter:** A feature used to restrict the packets displayed in Wireshark.

## Result

Network traffic was captured on the Kali Linux `eth0` interface while accessing an HTTPS website. TCP traffic on port `443` was filtered, and a stream was analyzed using the **Follow TCP Stream** feature.

The application data was not displayed in readable form because HTTPS uses TLS to protect transmitted information.
