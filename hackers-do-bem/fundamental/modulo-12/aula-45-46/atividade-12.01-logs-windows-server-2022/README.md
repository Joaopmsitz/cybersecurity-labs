# Activity 12.01 — Exploring Logs in Windows Server 2022

## Objective

Explore the main event logs available in Windows Server 2022 through Event Viewer (`eventvwr.msc`), identify different log categories, and use event filtering to narrow down the displayed records.

## Environment

- **Operating system:** Windows Server 2022
- **Access:** RDP
- **Tool:** Event Viewer (`eventvwr.msc`)
- **Logs analyzed:** Application, Security, Setup, System, and Forwarded Events

## 1. Accessing Event Viewer

Windows Server 2022 was started and accessed via RDP.

In the taskbar search field, the following term was entered:

```text
eventvwr.msc
```

The Event Viewer application was then opened.

## 2. Exploring Windows Logs

In the left pane of Event Viewer, the following option was expanded:

```text
Windows Logs
```

This section contains different categories of events recorded by the operating system.

The main available logs are:

### Application

Records events generated by applications and programs running on the system, including information, warnings, and errors related to software operation.

### Security

Records events related to system security, such as authentications, access attempts, policy changes, and activities associated with user accounts.

### Setup

Records events related to the installation and configuration of operating system components and software.

### System

Records events generated by the operating system itself, including information about startup, drivers, hardware, and system components.

### Forwarded Events

Allows events forwarded from other computers on the network to be centralized, which is useful in environments that use centralized log collection.

## 3. Exploring the Application Log

Within:

```text
Windows Logs → Application
```

the history of application events recorded on the server was examined.

Next, the first available event in the list was opened.

The details window displays information such as:

- **Log Name:** The log category in which the event was recorded.
- **Source:** The component or application responsible for generating the event.
- **Event ID:** The numeric identifier assigned to the event.
- **Level:** The event severity level, such as information, warning, or error.
- **User:** The user associated with the event.
- **OpCode:** The code identifying the operation associated with the event.
- **Logged:** The date and time when the event was recorded.
- **Task Category:** The specific category of the task associated with the event.
- **Computer:** The computer responsible for generating the event.

This information is important for analyzing an event's context and identifying its origin, severity, and time of occurrence.

After the analysis, the event window was closed.

## 4. Exploring the Other Logs

Still within:

```text
Windows Logs
```

the following categories were accessed:

### Security

The history of security-related events recorded by Windows Server was viewed.

These records can be used, for example, to investigate authentications, account changes, and other security events.

### Setup

The history of events related to system installation and configuration was viewed.

### System

The history of events generated by the operating system was viewed, including information related to services, drivers, and system operation.

### Forwarded Events

The log intended for events forwarded from other computers was viewed.

## 5. Accessing the Application Log Filter

After returning to:

```text
Windows Logs → Application
```

the Actions pane on the right was accessed.

Next, the following option was selected:

```text
Filter Current Log...
```

This feature allows the displayed events to be narrowed down using different criteria.

## 6. Exploring the Filtering Parameters

The Filter Current Log window provides several parameters that can be used to filter events.

### Logged

Allows a date and time range to be specified for the events to be displayed.

For example, the search can be restricted to events recorded during a particular period.

### Event logs

Allows the logs to be considered by the filter to be selected.

In this case, the Application log is selected by default.

### Event sources

Allows the sources responsible for generating events to be selected.

This makes it possible to focus the analysis on a particular application or system component.

### Task category

Allows the task category to be used as a filtering criterion.

In the context shown in the lab, this field cannot be edited.

### Keywords

Allows keywords associated with events to be used to narrow down the results.

These keywords can help identify particular types of events, such as information related to errors or security.

### Users

Allows events associated with specific users to be filtered.

This feature can be useful when investigating activities associated with a particular account.

### Computer(s)

Allows the computer associated with the events to be selected.

In environments with multiple computers and centralized event collection, this filter can help restrict the analysis to a specific machine.

## 8. Completion

After exploring the logs and the filtering tool, all windows were closed, keeping the RDP connection active for the next activity.

## Key Concepts

- **Event Viewer:** A Windows tool used to view and analyze events recorded by the system.
- **Windows Logs:** A collection of Windows event categories, such as Application, Security, Setup, System, and Forwarded Events.
- **Event ID:** An identifier used to distinguish event types.
- **Event Source:** The component responsible for generating an event.
- **Log Level:** Indicates the event category or severity, such as information, warning, or error.
- **Event filtering:** Allows displayed events to be narrowed down according to specific criteria.

## Activity Workflow

```text
Windows Server 2022
        ↓
Event Viewer
        ↓
Windows Logs
        ↓
Application / Security / Setup
System / Forwarded Events
        ↓
Filter Current Log
        ↓
Analysis of filtering criteria
```

## Result

The main logs available in Windows Server 2022 and the details associated with recorded events were explored. The Filter Current Log feature was also examined to identify the different criteria available for filtering system events.
