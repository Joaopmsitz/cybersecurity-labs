# Activity 7.06 — Local Full Backup with Duplicity

> **Program:** Hackers do Bem  
> **Stage:** Fundamental — Module 07  
> **Classes:** 27–28  
> **Environment:** Kali Linux  
> **Status:** Completed

## Objective

Perform a local full backup using Duplicity on Kali Linux and then restore the files to verify the integrity of the backup.

Duplicity performs encrypted backups and can store data in different destinations. In this lab, the backup will be stored locally in another directory on the system.

## Environment

- **Operating system:** Kali Linux
- **Tool:** Duplicity
- **Source:** `/home/aluno/Documentos/Conteudo`
- **Backup destination:** `/home/aluno/Documentos/ArmazenaBackup`
- **Restore directory:** `/home/aluno/Documentos/BackupRestaurado`

> Credentials used in the lab environment are not recorded in this README.

## 1. Switching to the Root User

The root user was used to perform the lab operations.

```bash
sudo -i
```

## 2. Creating the Content Directory

The `Documentos` directory was accessed, and the folder that would serve as the backup source was created:

```bash
cd /home/aluno/Documentos
mkdir Conteudo
ls
```

Output:

```text
Conteudo
```

## 3. Creating the File to Back Up

The `Conteudo` folder was opened:

```bash
cd Conteudo
nano teste.txt
```

The following content was entered in the file:

```text
Teste
```

This file would later be used to verify whether the restoration was successful.

## 4. Creating the Full Backup

The backup was performed using the following command:

```bash
duplicity /home/aluno/Documentos/Conteudo file:///home/aluno/Documentos/ArmazenaBackup
```

Output displayed by Duplicity:


The message:


indicates that no previous backup signature was available for comparison. Therefore, Duplicity performed a full backup.


## 5. Verifying the Backup Files

After the backup completed, the contents of the `Documentos` directory were checked:

```bash
cd ..
ls
```

Output:

```text
ArmazenaBackup  Conteudo
```

The `ArmazenaBackup` directory was created to store the data generated by Duplicity.

Next:

```bash
cd ArmazenaBackup
ls
```

Output recorded during the lab:

```text
duplicity-full.20240222T032821Z.manifest.gpg
duplicity-full.20240222T032821Z.vol1.difftar.gpg
duplicity-full-signatures.20240222T032821Z.sigtar.gpg
```

The filenames may vary depending on the date and time when the backup is performed.

The files stored by Duplicity include the manifest, the backup data, and the signature information required to manage the backups.

**Note:** The filenames above are preserved as recorded in the lab. Their embedded timestamp differs from the backup date shown in the preceding statistics.

## 6. Restoring the Backup

After creating the backup, the data was restored to a new directory:

```bash
duplicity file:///home/aluno/Documentos/ArmazenaBackup /home/aluno/Documentos/BackupRestaurado
```

Output:

```text
Nenhuma ação válida encontrada. Irá implicar 'restaurar' porque a fonte de url foi dada e o destino é um caminho local.
Os metadados remotos e locais estão sincronizados; nenhuma sincronização é necessária.
Last full backup date: Tue Oct 14 13:49:00 2025
GnuPG passphrase for decryption:
```

During this process, Duplicity uses the files stored in `ArmazenaBackup` to reconstruct the original content in the `BackupRestaurado` directory.

## 7. Verifying the Restored Files

After restoring the backup, the `Documentos` directory was accessed again:

```bash
cd ..
ls
```

Output:

```text
ArmazenaBackup  BackupRestaurado  Conteudo
```

The restore directory was opened:

```bash
cd BackupRestaurado
ls
```

Output:

```text
teste.txt
```

Finally, the contents of the restored file were checked:

```bash
cat teste.txt
```

Output:

```text
Teste
```

The restoration recovered `teste.txt` with the same content originally created in `Conteudo`, confirming that the data could be recovered from the backup.
