## Platform Activity vs. Repository Documentation

The public LetsDefend profile displays platform-wide performance metrics and alert-category activity. These figures are separate from the number of individual investigation reports published in this repository.

- **Platform activity:** metrics and alert-category values supplied by LetsDefend.
- **Repository documentation:** 0 individual reports currently organized in this catalog.

Not every alert investigated on the platform necessarily has a dedicated report in this repository.

## Investigation Methodology

1. **Alert Triage** - Review alert metadata, severity, assets and detection context.
2. **Evidence Collection** - Examine available logs, endpoint telemetry, processes, network activity and artifacts.
3. **Threat Validation** - Correlate indicators with threat intelligence and external analysis.
4. **Technical Analysis** - Distinguish observed evidence from assumptions and external context.
5. **Response Assessment** - Separate actions actually performed from recommended containment and remediation.
6. **Classification** - Record the verdict and its supporting evidence.

## Documentation Principles

- Conclusions must be supported by evidence.
- Missing telemetry must not be interpreted as proof that an activity did not occur.
- Threat intelligence and automated detections must be evaluated in context.
- MITRE ATT&CK mappings must reflect observed or sufficiently supported behavior.
- External write-ups are references for cross-checking, not proof of actions performed in this investigation.
- Platform verdicts and analyst conclusions must be distinguished when they differ.

## Scope

These are controlled LetsDefend training exercises. Findings and response actions refer to simulated scenarios and should not be interpreted as real-world incident response engagements.
