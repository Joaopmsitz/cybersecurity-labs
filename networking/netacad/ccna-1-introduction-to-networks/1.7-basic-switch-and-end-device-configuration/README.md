## Overview

This Packet Tracer activity consolidated the basic Cisco IOS configuration and IPv4 connectivity skills practiced throughout the previous labs.

The objective was to configure two Cisco switches and two end devices in a small wired LAN, including hostname configuration, password protection, password encryption, MOTD banners, IPv4 addressing, configuration persistence, and connectivity verification.

Unlike the previous guided labs, this activity provided dynamically generated requirements that had to be identified and implemented correctly.

---

## Objectives

* Configure hostnames on two Cisco switches
* Configure console and privileged EXEC security
* Encrypt plaintext passwords
* Configure MOTD banners
* Configure IPv4 addresses on switches and PCs
* Save device configurations
* Verify connectivity between end devices
* Validate the complete LAN configuration

---

## Lab Environment

### Network Devices

* Cisco Switch — Room-145
* Cisco Switch — Room-146

### End Devices

* Manager
* Reception

### Network Topology

```text
Manager ───── Room-145 ───── Room-146 ───── Reception
```

## Addressing

| Device    | Interface | IP Address     | Subnet Mask     |
| --------- | --------- | -------------- | --------------- |
| Room-145  | VLAN 1    | `10.10.10.100` | `255.255.255.0` |
| Room-146  | VLAN 1    | `10.10.10.150` | `255.255.255.0` |
| Manager   | NIC       | `10.10.10.4`   | `255.255.255.0` |
| Reception | NIC       | `10.10.10.5`   | `255.255.255.0` |

> The addressing values above correspond to the requirements generated by this specific Packet Tracer activity.

# Configuration Requirements

The activity required the following configuration on both switches:

* Hostname
* Console line password
* Privileged EXEC secret
* Password encryption
* MOTD banner
* Management IP address
* Configuration saved to NVRAM

The PCs were configured with the IPv4 addresses specified in the addressing table.

---

# Switch Configuration

## Hostname

The switches were configured with their assigned hostnames:

```text
Switch(config)# hostname Room-145
```

and:

```text
Switch(config)# hostname Room-146
```

---

## Console Security

Console access was protected using the line password specified by the activity:

```text
Room-145(config)# line console 0
Room-145(config-line)# password <LinePW>
Room-145(config-line)# login
```

The same configuration was applied to Room-146.

The `login` command enables password authentication on the console line.

---

## Privileged EXEC Security

Privileged EXEC mode was protected using the assigned secret:

```text
Room-145(config)# enable secret <SecretPW>
```

The same configuration was applied to Room-146.

`enable secret` is preferred over `enable password` because the secret is stored in a hashed form in the configuration.

---

## Password Encryption

Plaintext passwords were encrypted using:

```text
Room-145(config)# service password-encryption
```

The same configuration was applied to Room-146.

This prevents configured plaintext line passwords from appearing directly in the running configuration.

---

## MOTD Banner

A Message of the Day banner was configured to warn unauthorized users:

```text
Room-145(config)# banner motd "Authorized Access Only!"
```

The same requirement was applied to Room-146.

---

# IP Configuration

## Switch Management Interfaces

The switches were configured with management IP addresses through the VLAN 1 SVI.

### Room-145

```text
Room-145(config)# interface vlan 1
Room-145(config-if)# ip address 10.10.10.100 255.255.255.0
Room-145(config-if)# no shutdown
```

### Room-146

```text
Room-146(config)# interface vlan 1
Room-146(config-if)# ip address 10.10.10.150 255.255.255.0
Room-146(config-if)# no shutdown
```

The SVI provides an IP-based management interface for the switches.

---

## PC Configuration

The end devices were configured through:

**Desktop → IP Configuration**

### Manager

```text
IP Address:  10.10.10.4
Subnet Mask: 255.255.255.0
```

### Reception

```text
IP Address:  10.10.10.5
Subnet Mask: 255.255.255.0
```

Both PCs were configured within the same IPv4 subnet.

No default gateway was required for communication within this local subnet.

---

# Configuration Verification

The switch configurations were verified using IOS commands such as:

```text
Room-145# show running-config
```

and:

```text
Room-145# show ip interface brief
```

These commands were used to verify:

* Hostname
* Console configuration
* Password security
* MOTD banner
* Management IP address
* Interface status

The same verification process was performed on Room-146.

---

# Saving the Configuration

The completed configurations were saved to NVRAM:

```text
Room-145# copy running-config startup-config
Room-146# copy running-config startup-config
```

Saving the configuration ensures that the configuration is retained after a device reboot.

---

# Connectivity Verification

Connectivity was tested using the `ping` command.

Examples:

```text
Manager> ping 10.10.10.5
```

```text
Manager> ping 10.10.10.100
```

```text
Manager> ping 10.10.10.150
```

Successful ping responses confirmed that:

* The PCs had valid IPv4 configurations.
* The switches had valid management IP addresses.
* The devices were connected correctly.
* All devices were operating within the expected `10.10.10.0/24` subnet.
* Basic Layer 2 and Layer 3 connectivity was functioning.

# Key Commands

| ----------------------------- | ------------------------------------ |

| Save configuration            | `copy running-config startup-config` |
| Test connectivity             | `ping <ip>`                          |

# Key Takeaways

This lab reinforced the relationship between **device configuration, management addressing, and basic LAN connectivity**.

The most important concepts practiced were:

* Cisco IOS navigation and configuration modes
* Console authentication
* Privileged EXEC protection using `enable secret`
* Password encryption with `service password-encryption`
* Management access through an SVI
* IPv4 addressing and subnet masks
* Configuration persistence using NVRAM
* Basic connectivity testing with `ping`

A particularly important distinction is that the **switch management IP address is configured on `interface vlan 1`**, while the PCs receive their IP addresses through their NIC configuration.
